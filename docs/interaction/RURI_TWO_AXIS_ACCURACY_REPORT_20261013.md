## 3. WebとAndroidの推論一致問題は解決

- [Android Semantic Runtime Parity #38312365175](https://github.com/eltnegcellist/Android_English_character_for_baby/actions/runs/38312365175) **成功**。
- 根本原因：Native ORTのスレッド数1固定。Android側と比較ホスト双方を**標準スレッド設定へ戻す**ことで解消。
- ケース最小embedding cosine **0.9967217882**、分類確率の最大差 **0.0167342066**、margin最大差 **0.0257329287**。現在の相互再現性のテスト上は合格。
- ただしLinux Native Java版のCI結果であり、Galaxy S25 ARM64実機については別検証が必要。
- 経緯・根拠：Android `docs/interaction/ANDROID_RURI_PARITY_BLOCKER.md`（ファイル名は経緯保存のため旧名）。

## 4. 改善手順（Ruriだけで分類する方針を維持）

1. **否定・非完了・疑問の対照例を別途収集して教師ラベルを人が確認。** 「泣いていない」「眠くない」「まだ終わっていない」と肯定形を同じファミリーに入れ、分割を家族単位で行う。トピックにも否定が必要なのでTopicの既存ヘッドについても同様の実験が必要。
2. Interactionの否定・複合発話を追加学習し、**今回の67件は学習に混ぜず再評価用として固定**する（再学習後は完全独立ではないことも明示）。
3. Topic側の否定の挙動を対象に既存Topic headの再学習・別の棄却クラス導入を検討する。**日本語キーワードの否定検査やルールベースへ戻さない。**
4. 保護者の自然な日本語音声（複数話者・速度・雑音あり）→Moonshine ASR→Ruri Topic・Interaction→英文選択→Kiki発話まで実機評価。誤った健康・安全の断定、否定の誤解を優先審査。
5. 英文111組×3セット・333セットの音声試聴と文章の独立レビューを実施し、合格した範囲から実験スイッチを段階的に有効化する。
