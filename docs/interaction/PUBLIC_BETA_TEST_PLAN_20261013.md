## 現状：一般公開を保留する根拠

1. **否定・提案・安心させる複合文の意味反転**。Webの探索的67例は両軸56/67で一致したが、実音声の精度ではない。追加の単独Polarity実験は難問51例で35件（68.6%）しか正しく判定できず、誤って安心の言葉を消すリスクあり。**Polarity実験ヘッドは本番未採用**。
2. Android CIのNative ORT ↔ Web WASM Embedding parityには**再発/実行環境依存の可能性**が残る。成功ラン `38313204840` と後続失敗 `38316437759` が同じモデルを参照。最新のCI成功と実機ARM64の再現性を別々に確認すること。成功ラン単体では一般公開合格としない。
3. Kikiの自然さ、実際の保護者Moonshine音声ASR、333セットの第三者英文レビューは未完了。
4. Web PR #73/Android PR #38はDraft・main未統合。新Interactionは開発者スイッチ初期OFF。

## ベータテストのプロトコル

試験参加者の口頭/書面同意を得て、少なくとも異なる発話者・声質・速さ・静寂/生活音の環境を複数組み合わせる。最初は5人×20例×2環境（200試行）を目安とする。人数や評価数は性能・募集に応じて調整し、実データがない段階で達成済みと書かない。

| 項目 | 試行例（保護者が自然に読み上げる） | 主な注意点 |
|---|---|---|
| Topic単独 | ミルクだね／おてて動いてるね／眠たいのかな | 育児話題の正しい選択 |
| Interaction単独 | かわいいね／上手にできたね／どうしたの？ | 愛情、褒め、質問の区別 |
| Topic×Interaction | ミルクよく飲めたね／おむつ替え終わったかな／絵本読もうか | 333セットの適切なペア |
| 事実の否定 | まだ終わっていないよ／眠くないね／泣いてないね | 意味が逆転しないこと |
| 否定疑問・提案 | 絵本を読まない？／ミルク少し飲まない？ | 「読まない」という否定の事実にしない |
| 否定＋安心 | できなかったけど大丈夫だよ／泣かなくていいよ | 慰めや励ましの意図を落とさない |
| 会話の連続 | ミルクだね → かわいいね → おしまいかな？ | 前話題の持ち越し・勝手な合成の防止 |
| 入力の欠落 | 短い発話、言い直し、途中停止、雑音のみ | 誤検出・汎用英文への安全退避 |

試験結果は**音声原本をGitHubへアップロードしない**。各テストについて次の項目を保存する：個人が特定されない試行ID、任意の話者ID、機種、環境、意図した発話、Moonshine文字起こし、Ruri Topic候補/確率、Interaction候補/確率、選ばれたルート、英語3文、判定者による意味一致（OK/NG/判断保留）、否定反転の有無、Kiki発音（OK/NG）、推論時間、エラー状態。

必要最小限の文字起こしも個人情報の可能性があるので、参加者本人がローカルに保持するか、共有時に内容を除去・匿名化する。Android診断ログは今回、保存メッセージから日本語発話本文を除外した。

## 推奨する段階公開

1. 内部検証版（開発者のInteractionスイッチ初期OFF、既存機能への退行なし）。
2. 試験参加者への限定公開。実験スイッチONで十分な音声・否定テストを実施。誤分類の具体例をラベルレビュー後、Ruriの学習に還元する。
3. 合格した段階でPR #71（実験）、Web #72→#73、Android #37→#38の**依存関係とコンフリクトを再検査**して統合。ダブル適用を防ぐためmainとのdiffも確認。
4. 一般公開の直前に、本番のデフォルトInteraction=ONと設定保持・無効化操作を確認する。限定試験に合格していないならOFFのままにし、新二軸機能を公開済みと広告しない。
5. 公開後は匿名化した意味誤り数、モデルロード失敗、端末フリーズを評価し、必要に応じて機能を切り戻す。
