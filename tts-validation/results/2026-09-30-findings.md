# Misaki no-eSpeak discovery: BLOCKED before integration

## Scope and reproducibility

- Production baseline: `62f39abc095dd29a57d86a0efdef5400a2bb4293` (v1.9.12).
- Compared main: `0f8f04d3e942596f132578004bdc6de06e1066a1`.
- `LiteResponseEngine.kt` and `LiteSpeechStyle.kt`, including all extracted banks, are identical between those refs. Main itself has other changes; it is not v1.9.12.
- Python 3.12, Misaki 0.9.4, spaCy 3.8.7, en_core_web_sm 3.8.0; `G2P(trf=False, british=False, fallback=None)` with default `version=None`.
- Install the pinned **reference-only** environment using `pip install -r tts-validation/requirements-reference.lock`. Do not use `misaki[en]` for this probe.
- Run `python tts-validation/validate_g2p.py`. Expected exit code is **1**: the discovery harness cannot approve app integration. The generated JSON is archived as `g2p-discovery.json.gz` (gzip, original UTF-8 JSON). The summary is also available separately as `g2p-summary.json`.
- This reference environment deliberately exposes the existing number normalizer dependency for audit. It is **not** a non-GPL Android engine or a distributable runtime.

## Results

| Probe | Cases | Result |
| --- | ---: | --- |
| Fixed bank entries, name placeholders removed with existing app semantics | 202 | 202 resolved; no unknown words |
| Name insertion matrix | 780 | 780 unresolved |
| Initial core fixtures | 12 | 11 resolved; Hana unresolved |
| Extra stress inputs | 8 | 6 resolved; invented unknown word and Tsumugi detected |
| Independently specified pronunciation contrasts | 8 | 7 matched; music-related bass misread |

The 202 entries comprise 56 generic templates, 100 scene templates, 40 scene filler entries, and 6 neutral closer entries. These are bank entries, not 202 unique complete runtime utterances. Every fixed bank entry is covered; arbitrary generated combinations, arbitrary user names, and Full model output are not exhaustively covered.

Name stress covers all 156 reply templates with each of five sample spellings: Hana, Hana-chan, Aoi-chan, Haruto-chan, Tsumugi-chan. Templates without a name slot receive a name prefix to exercise the existing force-name path. This is a conservative input matrix, not an assertion that every combination is selectable in a real session. Hana itself is unresolved, so turning off chan is insufficient.

`peekaboo`, milk, tummy time, contractions, and the two basic number fixtures resolve. Read past/present and wind noun/verb contrast checks match. `The bass is low.` is intended as a musical reference (expected /beɪs/); the candidate emits /bæs/. The fish example also emits /bæs/. The sentence can be ambiguous in isolation; this test demonstrates that token coverage alone does not guarantee the intended pronunciation, rather than proving general homograph accuracy.

## Blockers

1. **License gate remains blocked.** English extras in Misaki's upstream pyproject include phonemizer-fork and espeakng-loader. Neither is installed in the selective reference environment; imports of their fallback paths are explicitly rejected. However num2words 0.5.14 declares LGPL in both metadata and its included COPYING. It must not be copied unchanged into a runtime whose acceptance rule excludes GPL-family dependencies. This does not establish that all Misaki code is GPL or that a future native implementation must use num2words.
2. **Dictionary provenance is not complete.** US gold/silver files are hash-recorded, and the repository declares Apache-2.0. Their detailed upstream source history and any separate data terms have not been established in this probe. No safe-data conclusion is inferred solely from the repository label.
3. **Name coverage fails.** Unknown output is detected both at token level and inside merged `❓` strings. It is not dropped, spelled aloud, or sent to eSpeak to make the test pass. A qualified independent name pronunciation policy is required before adoption.
4. **Kitten adapter is not qualified.** 66/202 fixed entries contain `ᵊ`, absent from Kitten's token table. Misaki's A/I/O/W/Y and default-version T are accepted alphabetic Kitten tokens but carry different meanings. In Misaki they represent diphthongs and a flap; passing them unchanged would silently produce semantically wrong inputs. Upstream-documented expansion is recorded only as a diagnostic, not an approved adapter. Vowel length, token spacing, style-row selection, and voice/speed behavior remain untested.

The Kitten archive matches the app's SHA-256 `16092117bfe591ddcd58d078e1454603b8e1caea46f85653b2c2efae76bd883e`. It contains espeak-ng-data, so simply reusing the original download/archive would retain the dependency. Only model, voice, token, README, and LICENSE files were extracted for inspection; no candidate deployment bundle was created. No dictionary fallback outputs were used as expected phoneme data.

## Next decision

Do not port or integrate this reference configuration. First establish dictionary provenance and the feasibility of a permissively licensed number/name path. A further candidate must also define a Kitten-specific phoneme adapter with independently reviewed expected results; it cannot claim parity from token membership alone. If these cannot be established without disproportionate repair work, compare another G2P or retain stable TTS. Only after all G2P/license gates pass may an isolated ONNX engine be tested.
